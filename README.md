# TaskFlow

ระบบจัดการงานและติดตามงานสำหรับสมาชิกและผู้ดูแลระบบ สร้างด้วย Next.js, Prisma, SQLite/LibSQL และ NextAuth.js

## ความสามารถ

- CRUD รายการงาน: เพิ่ม ดู แก้ไข และลบ
- ตรวจสอบข้อมูลด้วย Zod ทั้งในฟอร์มและ API
- สมัครสมาชิกและเข้าสู่ระบบด้วยอีเมล/รหัสผ่าน
- สมาชิกเห็นและจัดการเฉพาะงานที่รับผิดชอบ
- ผู้ดูแลเห็นและจัดการงานทุกคน และเปลี่ยนผู้รับผิดชอบได้
- ค้นหาชื่องาน/รายละเอียด และกรองตามสถานะ ความสำคัญ ผู้รับผิดชอบ และช่วงวันครบกำหนด
- REST API: `GET`, `POST`, `PUT`, `DELETE` พร้อมตรวจ session และสิทธิ์

## ความต้องการ

- Node.js 20.19 ขึ้นไป
- npm

## ติดตั้งและรัน

เปิด Terminal ที่โฟลเดอร์ `taskflow`:

```bash
npm install
```

สร้างไฟล์ `.env`:

```bash
cp .env.example .env
```

บน Windows PowerShell:

```powershell
Copy-Item .env.example .env
```

สร้างค่า `AUTH_SECRET` แล้วใส่ใน `.env`:

```bash
npx auth secret
```

ตัวอย่าง `.env`:

```dotenv
DATABASE_URL="file:./dev.db"
AUTH_SECRET="ใส่ค่าที่สร้างจาก npx auth secret"
```

สร้างฐานข้อมูลและ Prisma Client:

```bash
npx prisma migrate dev
npx prisma generate
```

โปรเจกต์ใช้ LibSQL adapter กับไฟล์ SQLite ในเครื่อง จึงไม่ต้องติดตั้ง Visual Studio C++ Build Tools

เริ่มใช้งาน:

```bash
npm run dev
```

เปิด [http://localhost:3000](http://localhost:3000)

## บัญชีและบทบาท

1. เลือก **สมัครสมาชิก** เพื่อสร้างบัญชี สมาชิกใหม่จะได้ role `MEMBER` โดยอัตโนมัติ
2. เข้าสู่ระบบด้วยอีเมลและรหัสผ่าน
3. สมาชิกเห็น/แก้ไข/ลบได้เฉพาะงานที่ตนรับผิดชอบ
4. ผู้ดูแลเห็นและจัดการงานของทุกคน รวมถึงเปลี่ยนผู้รับผิดชอบ

เพื่อทดลองสิทธิ์ผู้ดูแล ให้สร้างบัญชีก่อน จากนั้นเปิด Prisma Studio:

```bash
npx prisma studio
```

แก้ role ของบัญชีที่เชื่อถือได้เป็น `ADMIN` ผ่านตาราง `User` แล้วออกจากระบบ/เข้าสู่ระบบใหม่เพื่อโหลด role ใหม่ **ห้ามเพิ่มช่องเลือก role ในหน้าสมัครสมาชิก**

## วิธีใช้งาน

- กด **สร้างงาน** เพื่อเพิ่มงาน
- กรอกชื่อ รายละเอียด วันครบกำหนด สถานะ และความสำคัญ
- ผู้ดูแลเลือกผู้รับผิดชอบได้ สมาชิกจะถูกกำหนดเป็นผู้รับผิดชอบงานของตนเอง
- ใช้ช่องค้นหาและตัวกรองในหน้ารายการ
- กดแก้ไขหรือลบรายการตามสิทธิ์

สถานะ: `รอดำเนินการ`, `กำลังทำ`, `เสร็จแล้ว`

ความสำคัญ: `ต่ำ`, `ปานกลาง`, `สูง`

## REST API

ทุก endpoint ต้องเข้าสู่ระบบก่อน เรียกจาก browser session หรือส่ง session cookie ที่ถูกต้อง

| Method | Endpoint | รายละเอียด |
|---|---|---|
| `GET` | `/api/tasks?q=&status=&priority=&assigneeId=&dueFrom=&dueTo=` | รายการงานตามสิทธิ์และตัวกรอง |
| `POST` | `/api/tasks` | สร้างงาน |
| `GET` | `/api/tasks/[id]` | ดูงานหนึ่งรายการ |
| `PUT` | `/api/tasks/[id]` | แก้ไขข้อมูลที่ส่งมา |
| `DELETE` | `/api/tasks/[id]` | ลบงาน |

รูปแบบข้อมูลสำหรับสร้าง/แก้ไข:

```json
{
  "title": "เตรียมรายงาน",
  "description": "รวบรวมข้อมูลประจำสัปดาห์",
  "dueDate": "2026-11-01",
  "status": "TODO",
  "priority": "MEDIUM",
  "assigneeId": "ใช้ได้สำหรับ ADMIN เท่านั้น"
}
```

`assigneeId` ไม่บังคับสำหรับสมาชิกและจะถูกกำหนดเป็นบัญชีตนเองเสมอ ส่วนผู้ดูแลเลือกผู้รับผิดชอบได้ หากข้อมูลไม่ถูกต้อง API ตอบ `400`; ไม่ได้เข้าสู่ระบบตอบ `401`; ไม่มีสิทธิ์ตอบ `403`; ไม่พบรายการตอบ `404`

## ความปลอดภัย

- รหัสผ่านเก็บเป็น bcrypt hash ไม่เก็บข้อความ plain text
- role เริ่มต้นเป็น `MEMBER` และ API ไม่ยอมรับการกำหนด role จากผู้สมัคร
- API จำกัดข้อมูลตาม session ฝั่งเซิร์ฟเวอร์ ไม่เชื่อ owner/assignee จาก client
- `.env`, SQLite database และ Prisma Client ที่ generate ถูกละเว้นจาก Git
- เปลี่ยน `AUTH_SECRET` ใน production และอย่า commit secret
